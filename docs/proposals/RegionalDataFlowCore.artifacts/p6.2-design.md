# P6.2 design — rules / inherited_symbolic_fields + SymbolicFieldId routing

Session 22. Branch `keyed-instances`. The SECOND and LAST compile-time slice of P6.
COMPILE-TIME model + `-region-out` render ONLY. Codegen (`.rel`/`.h`/`.cpp`/`.stdout`)
MUST stay byte-identical. GREENFIELD: every gate is STRUCTURAL, never answer-equality.

P6.2 populates the two RESERVED-EMPTY routing fields (`RegionTemplate::rules`,
`RegionTemplate::inherited_symbolic_fields`) and mints the region-global
`SymbolicFieldId`. It mints NO `RuleActivationEdge` and touches NONE of the dormant
runtime half (`activation_edges`/`AddDerivation`/`RouteResults`). The five authorities
stay separate: `RegionalFactId`(P3), `BindingState`(P3), `DeclaredAccessPath`(P5),
`AccessPlan`(P4, the only codegen-driving one), `recursive_components`(P6.1). The
`SymbolicFieldId` is region-global FIELD identity for ROUTING; the trie spine is P8
(NOT built here).

## 0. Settled open questions (the grounding-loop STOPs)

**Q1 — HEADLINE: clause-source, not DataFlow-source.** SETTLED: clause-source.
Empirically forced: `corecursion_1 -df` (opt) shows the recursive UNION `merge.7` and
`tuple.2` both carry `table=%table:4 eqset=8` — ping and pong were CSE-merged onto ONE
model table, so the post-Optimize DataFlow graph CANNOT tell you "ping.field0 routes to
pong.field1". The PARSED CLAUSES retain per-relation identity
(`ping(A,B):add_edge(A,B).`, `pong(A,B):ping(A,B).`,
`ping(A,B):pong(A,X),add_edge(X,B).`). This is the SAME lesson that flipped P6.1's
insert-arm formulation to the origin projection. The frozen-relation FILTER
(`ParsedDeclaration::Of(pred).Id() ∈ R.relation_schemas`) covers the corpus: messages,
functors, `#foreign` and aggregate functors are excluded because they are never
`relation_schemas`. Multi-clause relations (ping has TWO clauses) are handled by making
each clause a separate producer rule and requiring EVERY producer of a head field to
agree before promotion (§5).

**Q2 — Codegen change? NO. Pinned.** SETTLED: no codegen change. Verified by
`grep -rn` — NOBODY outside `lib/Regional` reads `RegionTemplate::rules`,
`inherited_symbolic_fields`, `SymbolicFieldId`, `RuleRoutingProjection`, or even
`FrozenRegionalProgram::Region()`; the only cross-file hit is the field declaration
itself. `Program::Build` consumes `DataFlowGraph()`, never `Region()`. So
`.rel`/`.h`/`.cpp`/`.stdout` are byte-identical by construction. The exit gate re-runs
the OptDiff suite to pin it (SUITE PASS unchanged; only `-region-out` goldens move).

**Q3 — Render location + census. NO census count.** SETTLED: follow the P6.1 / P5
precedent — the new blocks carry NO census count (`RegionalCensus` is UNCHANGED, so the
`census:` line is byte-identical and no census golden churns). Rationale: `census` is the
region-SKELETON count (regions / ports / row-contracts); routing rules are derived detail
like `recursive_components`, not a skeleton entity. The `rule` and `shared-field` blocks
render AFTER the P6.1 `recursive-component` block, each in its OWN literal width (NOT
folded into `kind_w` — E-K5-PAD), gated on non-emptiness. Every existing region-golden
line stays byte-identical; the change is PURELY APPENDED lines (§6).

**Q4 — SymbolicFieldId interner home: `RegionInstanceRelations`.** SETTLED: peer of the
P5 `schema_table`, keyed on `(RelationId.v, ordinal)` → a fresh `SymbolicFieldId` per
(relation, ordinal). It is a DISTINCT domain from P5's `RelSchemaLocalId`: P5 interns
per-relation order-free SETS of ordinals (`(RelationId, sorted ordinal set)`); P6.2
interns per-(relation, SINGLE ordinal) FIELDS into ONE region-global flat id space. The
P5 firewall comment already reserves this: "the honest P5 stand-in for the eventual
region-global `(region, SymbolicFieldSet)` rep, which P6.2/P8 populate … REBUILT at P8,
never migrated." P6.2 promotes FIELD identity (the atoms); P8 rebuilds the binding-schema
trie over `SymbolicFieldSet` (the composites). No migration: P6.2 adds a new table beside
`schema_table`, does not touch it.

**Q5 — Negated / aggregate / @product body atoms: NO (positive frozen-relation preds
only) for the first cut.** SETTLED: only POSITIVE predicates whose
`ParsedDeclaration::Of(pred)` is a frozen relation participate. Justification:
(a) a negated body atom `!p(...)` is an anti-join FILTER — it routes no value into the
head; its head-shared variables are bound by a positive atom elsewhere. Minting a routing
edge for it would fabricate a value-flow that does not exist. This mirrors F18 (P3 mints
no intra-state edges for negation).
(b) an aggregate's summary variable is PRODUCED by the functor, not positionally routed
from a body field; the `over(){}` projection is a different semantic. Excluding it is a
sound UNDER-approximation (never over-unions).
(c) `@product` cross-product mates share NO variable, so the positive walk naturally emits
no pair between them; a positive `@product` body predicate reading a frozen relation IS
still walked as a positive pred (its own shared variables route normally). No special case
needed.
This is a documented feature gap (a clean under-approximation): a field that is only
provably shared THROUGH a negation/aggregate stays a singleton class. Sound.

**Q6 — RuleId: deterministic per-decl clause ordinal (HP-9).** SETTLED: a dense
`uint32_t` counter assigned by the walk `for schema in relation_schemas (E-order): for
clause in schema.decl.Clauses() (parse-order range)`. NO `ParsedClause::UniqueId`, NO
pointer order (the HP-9 rule, exactly like P6.1's `decl.Id()` ordering and P3's dense
ids). `relation_schemas` is already deterministic (insert-range walk then ascending
Tier-2 decl Id); `decl.Clauses()` is a stable parse-order `UsedNodeRange`.

## 2. Diff hunk — the region-global SymbolicFieldId interner

`include/drlojekyll/Regional/RegionInstance.h` — inside `struct

AFTER (`:582` insert):
```cpp
  // ==================== P6.2 region-global field interner ====================
  // A FIELD interner (peer of the P5 `schema_table`, DISTINCT domain): one
  // `SymbolicFieldId` per `(RelationId, ordinal)`, in ONE flat region-global id
  // space across all frozen relations. This is the routing authority's atom;
  // P8 rebuilds the composite `SymbolicFieldSet` trie over these atoms. NEVER a
  // `RelSchemaLocalId` (that is per-relation order-free SETS — a different
  // authority). Interned deterministically at freeze in
  // (relation_schemas E-order x ordinal) order (HP-9), so `SymbolicFieldId{0}`
  // is `relation_schemas[0]`'s field 0.
  std::map<std::pair<uint64_t, uint32_t>, SymbolicFieldId> symbolic_field_table;
  uint32_t next_symbolic_field{0u};

  // Intern (or look up) the field id for (relation, ordinal). PURE.
  SymbolicFieldId InternSymbolicField(RelationId relation, uint32_t ordinal) {
    std::pair<uint64_t, uint32_t> key{relation.v, ordinal};
    auto it = symbolic_field_table.find(key);
    if (it != symbolic_field_table.end()) {
      return it->second;
    }
    SymbolicFieldId id{next_symbolic_field++};
    symbolic_field_table.emplace(key, id);
    return id;
  }

  // Look up an already-interned field id (no mint). Aborts on a miss — every
  // (relation, ordinal) touched by routing is seeded by AssignSymbolicFields
  // BEFORE rules are built, so a miss is a build corruption.
  SymbolicFieldId SymbolicFieldOf(RelationId relation, uint32_t ordinal) const {
    auto it = symbolic_field_table.find({relation.v, ordinal});
    assert(it != symbolic_field_table.end());
    return it->second;
  }
```

Rationale: `RegionInstanceRelations` already hosts the P5 DAG and is stored by value on
`FrozenRegionalProgram`, so the interner lives beside its sibling with no header cycle.
`std::map` keeps iteration deterministic (belt; the ids themselves come from the seeding
walk order, not the map order). `SymbolicFieldId` seed VALUES are dense and reproducible.

## 4. Diff hunk — `BuildRuleRoutingProjections` (the clause-source walk)

`lib/Regional/Planning.cpp`, new static after §3.

```cpp
// P6.2: the CLAUSE-SOURCE routing walk. For every frozen relation, for every
// clause defining it, for every POSITIVE body predicate whose declaration is
// ALSO a frozen relation, emit (SymFld(body_decl, i) -> SymFld(head_decl, j))
// for each body arg pos i and head param pos j sharing a clause variable
// (ParsedVariable::Id() equality). A clause with no such pair is still emitted
// (empty body_to_head) so §5 sees its base-case producer. RuleId is a dense
// per-clause ordinal (relation_schemas E-order, then decl.Clauses() parse order)
// — HP-9, never a UniqueId/pointer.
//
// Negated/aggregate body atoms do NOT participate (Q5): only positive
// predicates whose Of(pred).Id() is in `rel_ids` — messages/functors/foreign
// are never frozen relations and drop out here. @product mates share no
// variable and emit no pair naturally.
static std::vector<RuleRoutingProjection> BuildRuleRoutingProjections(
    const RegionTemplate &R, RegionInstanceRelations &inst) {
  std::unordered_set<uint64_t> rel_ids;
  for (const RelationSchema &schema : R.relation_schemas) {
    rel_ids.insert(schema.id.v);
  }

  std::vector<RuleRoutingProjection> out;
  uint32_t next_rule = 0u;
  for (const RelationSchema &schema : R.relation_schemas) {
    const ParsedDeclaration head_decl = schema.decl;
    const RelationId head{schema.id};
    for (ParsedClause clause : head_decl.Clauses()) {
      RuleRoutingProjection proj;
      proj.id = RuleId{next_rule++};
      proj.head = head;

      for (unsigned g = 0u; g < clause.NumGroups(); ++g) {
        for (ParsedPredicate pred : clause.PositivePredicates(g)) {
          const ParsedDeclaration body_decl = ParsedDeclaration::Of(pred);
          if (!rel_ids.count(body_decl.Id())) {
            continue;  // not a frozen relation (message/functor/foreign) -> no route.
          }
          const RelationId body_rel{body_decl.Id()};
          for (unsigned i = 0u; i < pred.Arity(); ++i) {
            const uint64_t body_var = pred.NthArgument(i).Id();
            for (unsigned j = 0u; j < clause.Arity(); ++j) {
              if (clause.NthParameter(j).Id() == body_var) {
                out_pair_into(proj, inst.SymbolicFieldOf(body_rel, i),
                              inst.SymbolicFieldOf(head, j));
              }
            }
          }
        }
      }
      out.push_back(std::move(proj));  // stored even if body_to_head empty (base case).
    }
  }
  return out;
}
```

with a tiny dedup helper (a self-join can match the same `(i,j)` once per body pred, and
two body preds can match the same head field — both are legitimately distinct pairs; we
dedup EXACT duplicate pairs only so a repeated identical `(body,head)` from one pred is
counted once):
```cpp
static void out_pair_into(RuleRoutingProjection &proj, SymbolicFieldId b,
                          SymbolicFieldId h) {
  std::pair<SymbolicFieldId, SymbolicFieldId> p{b, h};
  if (std::find(proj.body_to_head.begin(), proj.body_to_head.end(), p) ==
      proj.body_to_head.end()) {
    proj.body_to_head.push_back(p);
  }
}
```

Rationale: `clause.NthParameter(j)` is the head's j-th variable, `pred.NthArgument(i)` the
body's i-th; `ParsedVariable::Id()` is clause-scoped (same name ⇒ same id within a
clause), so equality is the head↔body shared-variable test. `ParsedDeclaration::Of(pred)`
returns the FIRST (canonical) declaration, whose `Id()` matches `RelationSchema.id`
(== `decl.Id()`). Iterating `head_decl.Clauses()` returns all clauses of the relation
across its redeclaration group (ping's TWO clauses both appear). Distinct pairs sharing a
head field (a JOIN) are preserved — §5 recognizes ambiguity and refuses to union
join-mates.

## 5. Diff hunk — `PromoteSharedSymbolicField` (the fixpoint promotion)

`lib/Regional/Planning.cpp`, new static after §4.

### Semantics (EXACT)

Two seed fields `f_a`, `f_b` are UNIONED into one routing class iff they provably carry
the same value in EVERY derivation. The single primitive is per (head relation `H`, head
ordinal `j`):

> Union `SymFld(H,j)` with a source `s` iff EVERY producer rule of `H` sources `H.j` from
> exactly ONE frozen body field, and all those per-producer sources are the SAME class
> (under the current union-find `find`).

Precisely, for `head_field = SymFld(H,j)`:
- **ProducerRulesOf(H)** = `{ r in R.rules : r.head == H }` — ALL clauses of `H`,
  including base-case clauses with empty `body_to_head`. (This is why §4 stores empties.)
- For each producer `r`, **sources_j(r)** = `{ find(b) : (b, head_field) in r.body_to_head }`.
  - `sources_j(r)` EMPTY ⇒ `r` is a base-case producer of `H.j` (message/constant/negation
    fed) ⇒ H.j is NOT uniformly frozen-sourced ⇒ NO promotion. (corecursion ping: the
    `ping:add_edge` clause leaves `sources_j` empty ⇒ ping.0 never promotes.)
  - `sources_j(r)` size ≥ 2 (after `find`) ⇒ a JOIN feeds H.j from two distinct classes in
    ONE rule ⇒ ambiguous ⇒ NO promotion (never union join-mates; the F16 trap).
- If EVERY producer `r` has `|sources_j(r)| == 1` and all those singletons are the SAME
  class `{s}`, and `s != find(head_field)`: `union(head_field, s)`.

`R.inherited_symbolic_fields[f.v] = find(f)` for every seed field `f` (dense
representative vector, size == `inst.next_symbolic_field`).

### Fixpoint (F28)

The promotion is a union-find; `union` only ever MERGES classes, so the class count is
monotone non-increasing and bounded below by 1. The singleton test uses `find`-reduced
source classes, so a union performed on one head field can make a DIFFERENT head field's
two sources collapse to one class (e.g. `p(K):a(K); p(K):b(K)` stays split, but if `a.K`
and `b.K` are elsewhere unioned, a later pass sees `p.K`'s sources as one class and could
promote). Therefore iterate to convergence:

```cpp
static void PromoteSharedSymbolicField(RegionTemplate &R,
                                       RegionInstanceRelations &inst) {
  const uint32_t n = inst.next_symbolic_field;
  std::vector<uint32_t> parent(n);
  for (uint32_t i = 0u; i < n; ++i) parent[i] = i;
  std::function<uint32_t(uint32_t)> find = [&](uint32_t x) {
    while (parent[x] != x) { parent[x] = parent[parent[x]]; x = parent[x]; }
    return x;
  };
  auto uni = [&](uint32_t a, uint32_t b) {  // union-by-min (deterministic rep).
    a = find(a); b = find(b);
    if (a == b) return false;
    if (a < b) parent[b] = a; else parent[a] = b;
    return true;
  };

  // Group producer rules by head relation once.
  std::map<uint64_t, std::vector<const RuleRoutingProjection *>> by_head;
  for (const RuleRoutingProjection &r : R.rules) by_head[r.head.v].push_back(&r);

  bool changed = true;
  while (changed) {
    changed = false;
    for (const RelationSchema &schema : R.relation_schemas) {
      const auto it = by_head.find(schema.id.v);
      if (it == by_head.end() || it->second.empty()) continue;
      for (uint32_t j = 0u; j < schema.decl.Arity(); ++j) {
        const uint32_t head_field =
            inst.SymbolicFieldOf(schema.id, j).v;
        bool all_single = true;
        std::optional<uint32_t> agreed;  // the one source class, if any.
        for (const RuleRoutingProjection *r : it->second) {
          std::set<uint32_t> src;
          for (const auto &[b, h] : r->body_to_head) {
            if (h.v == head_field) src.insert(find(b.v));
          }
          if (src.size() != 1u) { all_single = false; break; }  // base or join.
          const uint32_t s = *src.begin();
          if (!agreed) agreed = s;
          else if (find(*agreed) != s) { all_single = false; break; }
        }
        if (all_single && agreed && find(head_field) != find(*agreed)) {
          if (uni(head_field, *agreed)) changed = true;
        }
      }
    }
  }

  R.inherited_symbolic_fields.assign(n, SymbolicFieldId{0u});
  for (uint32_t i = 0u; i < n; ++i)
    R.inherited_symbolic_fields[i] = SymbolicFieldId{find(i)};
}
```

Termination: each outer iteration either performs ≥1 real `union` (strictly reducing the
class count, floor 1) or performs none and exits. So ≤ `n` iterations. `#include
<functional>` is added (or hand-roll the recursion; `functional` is already transitively
available — belt: add it).

MULTI-CLAUSE correctness: `by_head[H]` holds ALL of H's clauses. corecursion's `ping` has
two producers (`ping:add_edge`, `ping:pong,add_edge`); the add_edge base case leaves
`sources_0` empty ⇒ ping.0 never promotes ⇒ `ping.0 ≢ pong.0` as a head-sourced promotion.
`pong`'s SOLE producer `pong:ping` sources pong.0 from ping.0 (singleton) ⇒
`union(pong.0, ping.0)`. So corecursion_1 ALREADY promotes: classes `{ping.0, pong.0}`,
`{ping.1, pong.1}` — pong inherits ping's fields, the "all producers agree" arm. This is
the P6.2 discriminator visible on an EXISTING carrier.

### ProducerRulesOf — precise definition

`ProducerRulesOf(H) = { r ∈ R.rules : r.head == H }`. This is the set of CLAUSES defining
`H` (one `RuleRoutingProjection` per clause of `H`, from §4). It is NOT "rules that
mention H in a body". A base-case clause (empty `body_to_head`) IS a producer — its
presence is what makes a multi-source head field refuse promotion.

The reconstruction-diffs sketch wrote `producers = ProducerRulesOf(rel_of(f_a)) ∪
ProducerRulesOf(rel_of(f_b))`; that union is INCOHERENT once `f_a` and `f_b` are fields of
different relations (a producer of `rel_of(f_a)` has head `rel_of(f_a)`, so it can only
carry pairs `(*, field-of-f_a)`, never `(f_a, f_b)`). The corrected, coherent primitive is
directional per head field: promote `SymFld(H,j)` to its unique frozen source across all
producers of `H`. Union-find makes the resulting relation symmetric and transitive. This
is the survivor of the §5 refactor; document it as the fix to the sketch.

```cpp
// the P6.1 recursive-component member-name lookup).
static std::string RelNameOf(const RegionTemplate &R, RelationId id) {
  for (const RelationSchema &s : R.relation_schemas)
    if (s.id.v == id.v) return std::string(s.decl.NameAsString());
  return {};
}

// "relName.paramName" for a SymbolicFieldId, via the interner's inverse. The
// interner is small; a linear scan of symbolic_field_table is fine and keeps
// the render side-effect-free.
static std::string SymFieldText(const RegionTemplate &R,
                                const RegionInstanceRelations &inst,
                                SymbolicFieldId f) {
  for (const auto &[key, id] : inst.symbolic_field_table) {
    if (id.v != f.v) continue;
    const RelationId rel{key.first};
    const uint32_t ord = key.second;
    for (const RelationSchema &s : R.relation_schemas) {
      if (s.id.v == rel.v)
        return std::string(s.decl.NameAsString()) + "." +
               std::string(s.decl.NthParameter(ord).NameAsString());
    }
  }
  return {};
}
```

## 7. The discriminating STRUCTURAL exit gate

### Gate assertions (all STRUCTURAL, greenfield — never answer-equality)

1. **PROMOTE (all producers agree).** In the new carrier, `SymFld(q,0)` and `SymFld(p,0)`

   `find(a.K) != find(p.K)` FAILS on that bug. This is the F16 trap made load-bearing.
