### Correctable defects folded (with empirical proof)

**C1 — CARRIER MODE-SPLIT (unanimous: R1, R2, R3, R4).** The design §7 carrier's mutual
recursion is a PURE COPY-FORWARDING cycle `q(K,V):p(K,V). / p(K,V):q(K,V).`. Empirically
(`grep recursive-component` on the verbatim §7 carrier) the `recursive-component C0 members=(p,q)`
line the design predicts in §6/§7 appears **only in nodf/none** — opt AND nocf canonicalize the
vacuous p↔q self-loop away (the documented "un-optimized modes surface vacuous self-loops opt
strips" behavior). The design's §6 golden and §7 assertion 3 test a line absent in the primary
(opt) mode.
FIX (empirically verified this session, all 4 modes byte-identical region skeleton +
`recursive-component C0 members=(p, q)` PRESENT in every mode): route p's recursive arm through a
JOIN, exactly like `corecursion_1`'s `ping(A,B):pong(A,X),add_edge(X,B).`. Replace
`p(K,V):q(K,V).` with `p(K,V):q(K,X),edge(X,V).` (`edge` a new `#message`). The promotion story is
UNCHANGED: `q`'s sole copy producer `q:p` still unions `q.K~p.K`/`q.V~p.V`, `lookup:q` still unions
`lookup.*~q.*`, and `p`'s two frozen base producers `a`/`b` still block `p.K` and keep `a.K`/`b.K`
distinct. Refuter 3's worry that "nonlinearity breaks p.V=q.V forwarding" is refuted: the class
`{lookup.V, p.V, q.V}` still forms via `q:p`'s union INTO `p.V` (union-find membership is symmetric
— p.V being blocked as a *head* is irrelevant to its class membership).

**C2 — F28 FIXPOINT NOT GATED (decisive: R2).** Every promotion in the exit-gate carrier is
single-pass-reachable (all unions are singleton-source), so a BUGGY single-pass impl (no
`while(changed)` loop) ships byte-identical against the carrier — the P6.1-style "gate that passes
a wrong impl" trap, applied to F28. FIX: add a dedicated fixpoint-forcing carrier
`p:a; p:b; a:c; b:c; c:src_c` (`fixpoint_force.dr`). Verified this session: its **nodf** E-order is
`c(E0), p(E1), a(E2), b(E3)` — head `p` is walked BEFORE its sources `a`/`b`, so a single pass sees
`p.K`'s two sources `{a.K},{b.K}` still DISTINCT (a,b not yet unioned to c) and under-promotes
`p.K`; only iteration 2 (after `a.K<-c.K`, `b.K<-c.K`) collapses them and promotes `p.K` into c's
class. The nodf/none region golden's `shared-field` member list is the byte referee: fixpoint →
`members=(c.K, p.K, a.K, b.K)`; single-pass bug → `members=(c.K, a.K, b.K)` (p.K missing). In **opt**
`p` is eliminated entirely (row-contracts `{c,a,b}`), so this discrimination is nodf/none-only —
the per-mode `.region` goldens already carry that (mode-faithful, P6.1 precedent).

**C3 — RENDER MIS-ORDERED (R2, R3).** Empirical E-order for the fixed carrier is
`lookup(E0), a(E1), b(E2), p(E3), q(E4)` — the `#query` relation `lookup` sorts FIRST. So
SymbolicFieldId seeds `lookup.K=F0 < p.K=F6 < q.K=F8`, union-by-min gives rep **F0=lookup.K**, and
members ascend `(lookup.K, p.K, q.K)` — NOT the design's `(p.K, q.K, lookup.K)`. RuleId walks E-order
so rendered rule ids are `R0(lookup), R3/R4/R5(p), R6(q)` (R1/R2 = a/b base cases, empty, unrendered
→ non-contiguous rendered ids). And with the C1 JOIN fix, `p`'s recursive rule R3 routes ONLY
`(q.K->p.K)` (p.V is edge-sourced, a message, unrouted). §4 corrected render in §4 below.

**C4 — Q5 NEGATION/AGG NOT EMPIRICALLY EXERCISED (R1, R3).** The exclusion of negated/aggregate
body atoms is sound-by-under-approximation but no negation/aggregate carrier is compiled in the
gate. FIX (no new dedicated carrier needed): the whole OptDiff suite re-runs at the gate, so the
EXISTING `negate_1`/`negate_6`/`d5_recursive_negate`/`aggregate_1`/`average_weight` region goldens
exercise Q5 — their `rule` lines must show routes ONLY through positive frozen bodies, never through
the anti-join or the `over(){}` summary. Add an explicit gate check: `negate_1`'s region golden
carries no route sourced from the negated predicate. `ParsedClause::PositivePredicates(g)` skips
them structurally, so risk is low; the pin makes it load-bearing.

**C5 — MULTI-REDECLARATION ROBUSTNESS (R4).** §4 walks `schema.decl.Clauses()` on a single
`ParsedDeclaration`. If a relation's clauses are ever split across redeclarations, one `schema.decl`
could miss producers → a missed base-case producer would WRONGLY promote a head field (F31 /
