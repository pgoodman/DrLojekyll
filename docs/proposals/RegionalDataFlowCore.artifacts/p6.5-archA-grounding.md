## §0 The bedrock finding (why this doc exists)

You picked **Architecture A** precisely because it was "the smallest reading that does real PRODUCT
work" — to escape accreting observer/test-justified code. **The grounding overturns that premise.**
At tip:

- **Exactly one authority reaches codegen** — `AccessPlan`, via `frozen->PlanFor(decl)` at
  `Build.cpp:447/504`. (So my earlier "arch-A would be the first time the model reaches codegen" was
  wrong, and the design repeated it — `AccessPlan` already does.)
- **The M3 recursive-component fixpoint emitter (`LowerRoundBody`, `Stratum.cpp:1691/1699`) emits ONE
  generic joint claim-round per SCC group** — identical for self- vs co-recursion and for fused vs
  joint. There is **no alternate fixpoint arm to select.** `EmitJoinFire`'s linear case is already
  index-driven (all-hash M3), so there's no P7-style pre-built machinery to flip on.
- Therefore the smallest achievable arch-A slice, **A0**, is a *certification shadow*: attach a
  `RecursiveEvaluationPlan{kJointRound,kFusedRound}` shadow field to the emitted `INDUCTION` region
  (excluded from Hash/Equals), stamped from `RecursiveComponent::fusion`, rendered as an `.ir`
  ` plan=` token, refereed by a membership-correspondence belt. **Codegen is byte-unchanged; the
  answer-equality gate is vacuous by construction (nothing forks).** It sits on the **P7b rung**
  (byte-unchanged shadow + honesty belt), NOT the P7 rung (real selector-driven flip).

**In one line:** the model-drives-codegen *payoff* (A1 — a structurally-different, answer-equal
fixpoint for a fused component) is blocked on **three** things, so every small arch-A step available
today is another shadow:

1. **No alternate codegen arm exists** — A1 is genuinely new emission (`LowerRoundBody`/`EmitJoinFire`
   surgery), not a selector flip.
2. **The open F16 gap in `binding_prefix`** (`Regional.h:204-211`) — an ordinal is marked preserved on
   *any* in-cycle identity route, without promotion's single-source guard, so `kFused` is not yet
   trustworthy as functional binding-preservation. A0 only *displays* the classification; A1 *depends*
   on it being correct.
3. **Possibly P8/P9 (the ordered trie / all-hash runtime)** — a per-key-partitioned fused loop may need
   a runtime structure that doesn't exist (refuter 3: A1 "may be UNREALIZABLE on the current runtime,
   not merely deferred").

## §1 What A0 would be (the infra floor, IF the owner wants it)

Not "model drives codegen" — honestly, **"a `RecursiveEvaluationPlan` authority + a `RelationId`↔scc
bridge + an advisory `.ir` token."** Value it genuinely buys (refuter-agreed): the authority exists as
a real peer of `AccessPlan`; the `RelationId`↔scc-group association (the single hardest missing piece
any recursive-band consumer needs) is built and de-risked; the `.ir` gains a fused/joint token. It does
**not** change the generated program.

Refuter-mandated corrections if A0 is ever built:
- **Build the `RelationId`↔scc association at FREEZE** (reuse `ComputeRecursiveComponents`' existing
  view/decl/stratum crossing), NOT via a post-Optimize `BackingTableOf(RelationId)→TABLE*` resolver —
  that re-introduces the exact CSE identity-loss that bit P6.1/P6.2.
- **Do NOT bless the fused/joint token into goldens while F16 is open** — either gate A0 on F16 closing
  first, or validate the classification against an independent oracle. Otherwise A0 freezes a
  possibly-wrong `kFused` label into blessed `.ir` goldens that a future A1 will trust.
- **Golden prediction correction:** `tc_nonlinear_diff` is `@differential`, so `LowerDRRounds` mints
  **TWO** induction regions (OVERDELETE `Stratum.cpp:1836` + INSERT `:1850`) → **two** `plan=fused-round`
  lines, not one. (All 3 refuters verified this; the design's §4 was wrong.)
- **Drop the "first answer-equality gate" framing** — vacuous when codegen is byte-identical; the
  operative A0 gate is byte-stable codegen + the structural belts.
- The always-on `V-EVAL-BIJECTION` abort rests on a stratum↔merge_set correspondence that can *legitimately*
  split at message-seam strata (a P6.1 component may map to multiple M3 `merge_set_id`s) — it must
  tolerate that or it aborts on a valid program.

## §2 The real fork (the [OWNER STOP])

The honest conclusion is that **there is no small cut that makes the model do real product work right
now** — the model-drives-codegen endpoint is blocked on larger prerequisites. The options:

- **(a) Land A0 as explicitly-labeled infra** toward a multi-session A1 — accept it's a shadow, but it
  builds the authority + the freeze-side bridge and de-risks them. (With every §1 correction.)
- **(b) Attack the A1 blockers directly** — close the F16 join-multiplicity gap in `binding_prefix`
  (a real correctness cut, testable), and/or scope the new fused-round codegen arm. This is where the
  real divergence lives; it's multi-session.
- **(c) Re-sequence / strategy** — if A1 needs P8/P9 (a runtime range/trie) before the model can drive
  a *different* fixpoint, then P8/P9 may have to precede P6.5-real, and the phase ladder needs
  reordering. This is the "reconsider the endpoint" conversation the evidence now points to.
