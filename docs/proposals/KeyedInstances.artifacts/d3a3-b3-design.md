### 1.2 The parameterized builder (ONE function)

Replace both `*FromRegistry` twins with:

```cpp
// D3.a.3 g2: the ONE demand-injector builder (forcer ⊕ retract). The forcer's
// payload rides the ADD vector; the retract's rides the DEL vector; the
// non-payload vector, when present, is kEmpty. The retract is only ever over a
// differential message (its dispatcher's third conjunct), so it always has BOTH
// vectors; a forcer over a MONOTONE message has the single ADD vector only.
static std::optional<ProgramProcedure> BuildQueryInjectorFromRegistry(
    ProgramImpl *impl, Context &context, ParsedQuery query,
    const QueryDemandForcing &entry, bool is_retract) {

  ParsedDeclaration query_decl(query);
  const ParsedMessage message = entry.message;
  assert(message.IsReceived());
  assert(!is_retract || message.IsDifferential());   // delta A (retract-only)
  assert(message.Arity() == entry.bound_params.size());

  // [F] ALWAYS-ON handler fence (delta B, ADV-8): a map MISS default-inserts a
  // nullptr callee that codegen dereferences (release SIGSEGV, no diagnostic).
  // Always-on so it survives NDEBUG for BOTH injector kinds (the forcer twin's
  // old assert was compiled out under N fabricated messages — §2).
  if (!context.messsage_handler.count(message)) {
    fprintf(stderr,
            "error: demand injector (%s): the fabricated demand message has "
            "no handler procedure\n", is_retract ? "retract" : "force");
    abort();
  }

  auto proc = impl->procedure_regions.Create(
      impl->next_id++, ProcedureKind::kQueryMessageInjector);
  proc->has_raw_use = true;

  for (unsigned param_index : entry.bound_params) {
    const auto var =
        proc->input_vars.Create(impl->next_id++, VariableRole::kParameter);
    var->parsed_param = query_decl.NthParameter(param_index);
  }

  std::vector<TypeLoc> col_types;
  for (auto i = 0u; i < message.Arity(); ++i) {
    col_types.push_back(message.NthParameter(i).Type());
  }

  // Vector roles (deltas C/D). ORDER: add_vec ALWAYS created before del_vec —
  // matches BOTH twins' id stream (forcer :414→:419, retract :531→:533).
  VECTOR *add_vec = nullptr, *del_vec = nullptr;
  if (is_retract) {
    add_vec = proc->vectors.Create(impl->next_id++, VectorKind::kEmpty,
                                   col_types, 0);
    del_vec = proc->vectors.Create(impl->next_id++, VectorKind::kParameter,
                                   col_types, 0 /* disambiguation */);
  } else {
    add_vec = proc->vectors.Create(impl->next_id++, VectorKind::kParameter,
                                   col_types, 0 /* disambiguation */);
    if (message.IsDifferential()) {
      del_vec = proc->vectors.Create(impl->next_id++, VectorKind::kEmpty,
                                     col_types, 0);
    }
  }
  VECTOR *const payload_vec = is_retract ? del_vec : add_vec;  // delta E

  SERIES *seq = impl->series_regions.Create(proc);
  proc->body.Emplace(proc, seq);

  VECTORAPPEND *append = impl->operation_regions.CreateDerived<VECTORAPPEND>(
      seq, ProgramOperation::kAppendQueryParamsToMessageInjectVector);
  seq->regions.AddUse(append);
  append->vector.Emplace(append, payload_vec);
  for (VAR *param_var : proc->input_vars) {
    append->tuple_vars.AddUse(param_var);
  }

  CALL *call = impl->operation_regions.CreateDerived<CALL>(
      impl->next_id++, seq, context.messsage_handler[message]);
  seq->regions.AddUse(call);
  call->arg_vecs.AddUse(add_vec);                    // delta F: add always first
  if (del_vec) {
    call->arg_vecs.AddUse(del_vec);                  // empty (force) / payload (retract)
  }

  RETURN *ret = impl->operation_regions.CreateDerived<RETURN>(
      seq, ProgramOperation::kReturnTrueFromProcedure);
  seq->regions.AddUse(ret);

  return proc;
}
```

**Id-stream byte-identity — the load-bearing claim, per case:**
- **mono-force** (`message.IsDifferential()==false`): proc, N vars, add_vec,
  call. IDENTICAL to today's forcer (:396→:414→:434, no del_vec).
- **diff-force** (`-demand-retract` on): proc, N vars, add_vec, del_vec, call.
  IDENTICAL to today's forcer (:414→:419→:434 — add before del).
- **retract**: proc, N vars, add_vec, del_vec, call. IDENTICAL to today's
  retract (:531→:533→:548 — add before del). The `is_retract` branch creates
  add_vec FIRST (matching :531 add before :533 del), so the two `next_id++`
  land on the same ids as today.

The CALL's `arg_vecs` order (`add_vec` then optional `del_vec`) reproduces all
three today-shapes: mono-force = [add]; diff-force = [add, del(empty)]; retract
= [add(empty), del]. Vector KINDS per position are unchanged. **Zero emitted-IR
delta.**

### 1.3 The unified dispatcher (ONE function)

Fold `BuildQueryForceProcedure` (:452-484) and `BuildQueryRetractProcedure`
(:566-582) into:

```cpp
// D3.a.3 g2: the ONE injector dispatcher. Registry match is (query,
// BindingPattern)-keyed (the second belt — ParsedQuery::operator== compares
// DeclarationContext=(name,arity) ONLY, so two adornments of one name would
// cross-wire without the BindingPattern conjunct); the retract arm additionally
// gates on the fabricated message's differentialness. The user @first forcing
// surface is FORCE-ONLY (user forcing messages get no retract arm).
static std::optional<ProgramProcedure> BuildQueryInjectorProcedure(
    ProgramImpl *impl, Context &context, ParsedQuery query, bool is_retract) {

  if (context.demand_forcings) {
    for (const QueryDemandForcing &entry : *context.demand_forcings) {
      if (entry.query == query &&
          ParsedDeclaration(entry.query).BindingPattern() ==
              ParsedDeclaration(query).BindingPattern() &&
          (!is_retract || entry.message.IsDifferential())) {   // retract belt
        return BuildQueryInjectorFromRegistry(impl, context, query, entry,
                                              is_retract);
      }
    }
  }
  if (!is_retract) {
    if (auto pred = query.ForcingMessage()) {
      return BuildQueryForceProcedureImpl(
          impl, context, query, ParsedClause::Containing(*pred), *pred);
    }
  }
  return std::nullopt;
}
```

## §2 DELIVERABLE 2 — THE [F] ALWAYS-ON GUARD (ADV-8)

**Site:** the forcer's `assert(context.messsage_handler.count(message) && "…")`
(Build.cpp:393-394). **Predicate:** hardened to the always-on `if(!count){
fprintf; abort(); }` fence the retract twin already carries (:508-512). In the
dedup this is a SINGLE fence in `BuildQueryInjectorFromRegistry` (§1.2), which
is exactly the "the [F] dedup obligation unifies both" the retract comment names
(:503-507).

**Why it matters under N fabricated messages (the release SIGSEGV):**
`context.messsage_handler[message]` (the CALL callee at :435/:549) is a
`std::unordered_map::operator[]` — a MISS **default-inserts a nullptr**
`ProgramProcedure` handle. The forcer's guard is `assert(...)`, compiled OUT
under NDEBUG (release/bench builds). With multi-adornment, N fabricated demand
messages are minted (`demand__q_bf`, `demand__q_fb`, …); a `BuildIOProcedure`
registration bug that drops ONE message's handler (or a forcing-registry entry
naming an unregistered message) yields, in release, a nullptr CALL callee that
codegen later dereferences — a silent SIGSEGV with no diagnostic. The always-on
fence turns that into a loud, located abort in EVERY build config. Under
single-adornment the risk was one message; under N it scales with the fabricated
count, so the asymmetry (§5.1 row #20 HAZARD) must close as multi-adornment
lands.

**[BYTE] (D2):** the fence emits nothing on any passing program (the handler is
always registered for a real fabricated message — Procedure.cpp:706, §5.1 row
#21, N-safe). No golden moves; SUITE unchanged. Its teeth fire only on a
corrupt build, which no suite program produces — covered by inspection + parity
with the retract twin's landed behavior (no new suite case can induce a missing
handler; a dedicated death test would need to hand-corrupt `messsage_handler`,
out of scope and lower-value than the §3 inline teeth).

## §3 DELIVERABLE 3 — DESIGN-1 INLINE TEETH (the vehicle b2 g1 rides)

### 3.1 The gap, precisely (why the pure belt is not enough)

The pure belt `CheckInstanceInputArm` (Rel.cpp:4906-4952, death-tested by
`InputArmTest.cpp`) is a **separate re-derivation** that covers only:
- (a) the input-drain-ROLE admit (a diff-input drain is kNetAddition/kNetRemoval
  only), and
- (b) the input-arm both-signs provisioning (dr_ok ±).

It deliberately detects "differential input" STRUCTURALLY (`table_vecs`
kNetRemoval, :4927) so it needs no TABLE deref → it is fake-table-testable.

**Two inline checks have NO teeth at all:**
1. **V-INST-EFFECT totality** (:4292-4408) — the full regime-split effect
   multiset: `drains == (input_diff?3:2)`, `demand_drains==1`,
   `input_drains==(input_diff?2:1)`, `demands==1`, `leaves==1`, `rebuilds==1`,
   `rebuild_sign==1`, `emits==1`, `olds==1`, and the diff-split `counters==2 &&
   counter_signs==0 && crossings==2 && appends==2` (:4365-4377). A regression
   minting 1 counter under a diff pub, or dropping a crossing/append, is caught
   ONLY here, on a real build — no unit pins it. The pure belt does NOT count
   these.
2. **V-INST-DRAIN input arm inline** (:4592-4624) — fires FIRST on a real build
   (before the :4627 belt); uses `TableIsDifferential` (real deref), so it is
   the AUTHORITATIVE check, yet only the belt's re-derivation is tested.

**A hand-built fake flow cannot reach either** (feasibility proof at code): the
census recount (:3958-4020) runs BEFORE V-INST-EFFECT (:4280+) and calls
`expect(kSubgraphInstantiate, exp_instance, …)` where `exp_instance` derives
from `ResolveLiveRecognition(impl, query)` + `query.RecognizedSubgraphs()`. A
fake flow with an instantiate op but no matching `RecognizedSubgraph` aborts at
the census ("subgraph instantiates: derived 1, expected 0") — a SIGABRT for the
WRONG reason. Reaching the inline checks REQUIRES a real `Query` with real
recognitions + real tables (`TableIsDifferential`). **→ a real compiled flow is
mandatory; the teeth cannot be faked.**
